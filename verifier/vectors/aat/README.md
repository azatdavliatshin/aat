# AAT-01 test vectors (ours)

These vectors are **ours**. They are derived from our reading of
`draft-niyikiza-oauth-attenuating-agent-tokens-01`, not from its author, and
the draft publishes none. They record what this verifier does with that
reading; where the draft is silent the expected outcome is the strictest
reading (see the `draft unspecified` tags in `src/profiles/aat01*.ts`). Do not
cite them as the draft's conformance suite.

They are generated by `src/testing/aat-vectors.ts` (`npm run vectors:aat`) and
are deterministic: Ed25519 keys come from fixed seeds (public JWKs are in the
files, private seeds are in the generator), timestamps and `jti` values are
fixed, and Ed25519 signatures are deterministic, so regeneration reproduces
the files byte for byte. `test/aat01.vectors.test.ts` checks that.

## File shape

One JSON object per file, named after `name`:

| Member | Meaning |
|---|---|
| `name`, `description` | identifier and what the vector shows |
| `draft` | `"01"` |
| `now` | verification time (NumericDate) |
| `trust_anchors` | array of public Ed25519 JWKs trusted as root issuers |
| `chain` | root-first array of compact JWS |
| `request`, `pop` | optional: `{tool, args}` and the PoP JWT; when present, steps 6 and 7 run |
| `options` | verifier limits that differ from the defaults (`maxTokenLifetime` is always 1000) |
| `expect` | `{outcome: "accept"}` or `{outcome: "reject", code, check}` |

`code` is `I1`..`I6` for the invariants of §4 or the class of the failure
(`signature_invalid`, `jti_cycle`, `authorization_denied`, ...); `check` is the
name of the check in this verifier that fails first. Both are ours, not the
draft's.

## Coverage

41 vectors: a valid chain per depth 0 to 3 (with PoP); each invariant I1 to I6
violated at least once; `alg: none`; a wrong parent key; a `jti` cycle; a
`par_hash` of the wrong parent; PoP replay (`iat` outside the window); a leaf
argument outside the closed world; and for each of the nine constraint types
one narrowing (accept) and one widening (reject).
